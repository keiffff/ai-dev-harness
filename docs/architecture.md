# Agent Architecture

この構成では、判断をCodex（main agent）に集約し、周辺のスキル、subagent、advisor、実行ハーネスが支える。

## 中心

Astraのmain agentであるCodexが、リポジトリの文脈把握、実装、差分確認、テスト確認を担う。

subagent や advisor は補助であり、最終判断、インターフェース、互換性、fallback、Git操作は main agent に残す。

外部情報源の調査を担うresearch scoutも同じ境界で扱う。scoutは最新情報と参照元のURLを集めるが、一次情報の確認、リポジトリの文脈への適用、最終判断はmain agentに残す。

## レビュー表現

main agentは、レビュー対象の内容だけでなく、開発者が何を確認するかに合わせて表現を選ぶ。正確な比較には表、依存関係にはグラフ、状態遷移や処理順序にはフロー、時間による変化にはタイムライン、階層にはツリーを使う。複数の表示や情報配置がレビューに必要な場合は、単独で開けるHTMLを使う。

可視化は、判断や契約を記録した元のMarkdown、OpenSpec、コード、スキーマを置き換えない。生成したHTMLは元資料から作るレビュー用の表現として扱い、開発者の指摘をmain agentが元資料へ反映してから再生成する。

## 開発者の役割

開発者は作業を細かく指示し続けるのではなく、AI が知らない文脈を与える。開発者が以下の事項を持ち、判断する。

- 目的
- 制約
- 事業文脈
- 仕様判断
- やらないこと
- 停止判断
- 最終判断

## 介入を残す理由

AIエージェントは、足りない文脈をもっともらしく補って作業を進めることがある。完全に自動化すると、仕様の不足、既存契約、運用上の前提、レビューの粒度を開発者が判断する前に実装が進みすぎる。

この構成では細かい作業をエージェントに任せる一方、インターフェース、永続化、互換性、fallback、Git、cloud、secret、productionについて判断できない場合は停止する。
