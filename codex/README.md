# Codex Configuration

Codexを実務の開発フローへ組み込むための設定例と、運用に必要なファイルをまとめたディレクトリです。

`~/.codex` は実行時の配布先ディレクトリです。ここには、特定プロジェクトの固有事情を含まない共通設定を配置します。

## Role

Codex はメインエージェントとして、リポジトリの文脈把握、実装、検証、差分確認、そして最終判断までを一貫して担います。判断のすべてをモデルの自律性に委ねるのではなく、常時読み込むルール、必要に応じて参照するスキル、外部から実行を制御・停止するフックやラッパーを明確に切り分け、期待する振る舞いを実行環境の仕組みとして組み込みます。

## Policy

- 常時読み込むルールは簡潔に保つ
- 常時読む必要のない詳しい知識や作業手順は、スキルや参照資料へ切り出す
- 文章作成、コードレビュー、デバッグ、OpenSpec、クラウド・CDK 運用などを用途別のスキルに分割する
- subagent は対象範囲を限定した調査や独立したレビューに活用し、最終判断と Git 操作はメインエージェントが担う
- 長期化したタスクは安全な工程の節目で handoff を提案し、明示的な承認を得たうえで、必要な文脈のみを新規タスクへ引き継ぐ
- プロジェクト固有の事情は各リポジトリ側に保持し、当リポジトリには汎用化した運用手法のみを集約する

## Contents

- `AGENTS.md`: Codex が常時読み込む共通ルール
- `config.example.toml`: approval、sandbox、model、ツールの各境界を定義した設定例
- `skills/`: 作業手順、レビュー、デバッグ、文章作成、アドバイザー呼び出しなどを管理するスキル群
