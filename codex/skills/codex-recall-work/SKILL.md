# Recall Work

Use the current request to identify the work, intended outcome and relevant prior decisions. This is preparation for that work, not a replacement summary task.

The private library is linked at `references/library`. Read its entry index, then search the topic, affected owner, symptom or earlier decision with `rg`. Open matching records and their directly relevant source or executable asset. Do not load the whole corpus. If the binding is absent, continue from available evidence; do not invent history or search unrelated chats.

Distinguish user decisions from agent proposals and later corrections. Check historical assumptions against the current source or live state where the intended action depends on them. An old record is neither current proof nor current permission. Preserve concrete reproduction conditions, failed approaches and the reason for a decision; do not replace them with an abstract maxim.

When a matching runnable verification asset exists, inspect its documented scope and execution boundary, then run its supported entrypoint for the relevant behavior. Add only uncovered verification. If it cannot apply, retain the concrete incompatibility or failure in the work evidence before substituting another method. Reading a helper does not establish that its verification ran.

Continue the original task using what was learned. Keep the requested outcome separate from completed intermediate operations: finding a record, repairing a tool, running an experiment, or writing its report does not resolve an outstanding implementation or improvement request. Use the observed result to choose the next relevant action within the existing authority.

When work reveals a correction, stale claim or reusable verification improvement, use `codex-learn-from-work` to update the owning asset. Do not claim that a remembered lesson prevented recurrence until its use and effect are observed.
